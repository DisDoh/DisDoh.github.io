02.About the App

The App allows users to encode and decode small files into the .aiz format using a trained model-based key, optionally apply a mask password, and manage, train, import, export, or back up compatible models. Encoded files may be shared using external apps or services. The App is an experimental technical tool, not a certified secure-storage or encryption service.

04.Experimental Security and Risks

The App's model-based encoding approach has not been represented as a replacement for independently audited cryptographic software. Protection depends on several factors, including the secrecy of the trained model, whether a mask password is used, and how models and files are distributed.

  • The generic/default model must not be used to protect sensitive files.
  • For private files, create or import your own private model.
  • An exposed, reused, or widely shared model can weaken protection.
  • If an attacker obtains both an encoded file and its matching model, the file may be recoverable, especially without a separate mask password.
  • Use vetted encryption tools for highly sensitive, regulated, or critical material.

The App does not guarantee confidentiality against every possible attack.

05.Models, Passwords, and Backups

Decoding requires the correct compatible model and, if a mask password was used, the matching password. You are responsible for keeping secure, accessible backups of your models and remembering your passwords. Loss of the required model or password may make an encoded file permanently unrecoverable. A password is not stored in plaintext inside the .aiz file according to the App's published description; this does not remove the need to protect passwords and model files.

06.File Size, Accuracy, and Integrity

The published workflow is intended for files of up to approximately 500 kB. Larger files should be compressed or split before encoding. Encoding or decoding may fail because of model incompatibility, insufficient reconstruction accuracy, corrupted data, device limits, or other technical issues. Always verify decoded files and preserve independent backups of important originals.

07.File and Model Sharing

You decide whether and how to share .aiz files, models, passwords, and original files. External messaging, email, and cloud services have their own privacy and security practices. For stronger separation, avoid sending a private model together with its encoded files, and use a trusted channel where possible.
